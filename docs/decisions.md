# Decisions

Tool and architecture choices, in the order they were made. Open source first.

| # | Decision | Chosen | Why / alternatives |
|---|---|---|---|
| 1 | First scope | Consents (3.3.1) + Accounts (2.4.2) | Phase 2 data sharing: consent lifecycle and cross-endpoint consistency. Phase 1 open data was simpler but has no consent or security. Accounts 2.5.0 is still beta. |
| 2 | Transformations | PySpark on Kubernetes | Replaces dbt (used in payer-data-readiness); closer to production data platforms. |
| 3 | Table format | Apache Iceberg 1.12.0 | Engine-neutral; Delta was the alternative. |
| 4 | Iceberg catalog | JDBC catalog in Postgres (CloudNativePG) | Safe for concurrent commits with one small service. REST catalog (Lakekeeper, Polaris) is closer to production but one more service; the Hadoop catalog on S3 is unsafe for concurrent writes. |
| 5 | Object store | SeaweedFS 4.54 (all-in-one, S3 gateway) | Apache 2.0 and active. MinIO's repository was archived (last release 2025-10-15). Garage is AGPL; Ceph RGW too heavy for kind/CI. |
| 6 | Spark | 3.5.9 (Scala 2.12, Java 17) | Long-lived line, most common in production. |
| 7 | Local Kubernetes | kind v0.33.0 (node v1.37.0) | Runs the same way on a laptop and on GitHub runners. |
| 8 | Installs | Helm charts with pinned versions and values files | CloudNativePG 0.29.1, SeaweedFS 4.54.0, Spark Operator 2.6.0. |
| 9 | Mock transmitter | ~~Same approach as the official [mock-api](https://github.com/OpenBanking-Brasil/mock-api): [openapi-mock](https://github.com/muonsoft/openapi-mock) on the official specs, plus a defect proxy~~ Replaced by 13 | The official images cover Phase 1 only and are frozen at v1.0.0-rc5.3 (2024). |
| 10 | Pinning the specifications | Downloaded from [OpenBanking-Brasil/openapi](https://github.com/OpenBanking-Brasil/openapi) at a fixed commit, checked by SHA-256 (`make specs`) | The upstream repository declares no license, so the files are not redistributed here. Vendoring them was the alternative (offline, visible diffs). |
| 11 | Spec linter | Spectral 6.17.0, Docker image pinned by digest | No Node.js on the host or in CI. 6.17.1 was ten days old when chosen. |
| 12 | Lint ruleset and failure policy | `spectral:oas` (recommended) plus `ofb-*` rules for the conventions every pinned operation follows; fail on errors only | Warnings are reported and the known ones listed in [spec-findings.md](spec-findings.md). Each `ofb-*` rule must fire on a defective fixture, so a rule that silently matches nothing fails CI. |
| 13 | Mock transmitter (revises 9) | Own synthetic transmitter (Python, FastAPI) over a seeded dataset, with consent state; defects injected by a separate proxy of our own (item 2b) | openapi-mock 0.3.9 on the pinned specs returned random data on every call, no state, no `x-fapi-interaction-id` header and out-of-spec values (year 3202, currency `QSN`): the clean baseline would already be defective and business rules would have nothing coherent to check. See [transmitter.md](transmitter.md). |
| 14 | Python dependencies | uv 0.13.6 with `uv.lock` (resolution limited to packages at least two weeks old); images on `python:3.13-slim-bookworm` pinned by digest | pip-tools with hashed requirements was the alternative: standard tools, slower and more verbose. |
| 15 | Response validation | openapi-core 0.23 | Validates status, headers, content type and body (with `$ref`, `pattern`, `format`) against OpenAPI 3.0. Alternatives: plain jsonschema on extracted schemas (reimplements the rest), Schemathesis already in item 2 (mixes items 2 and 3). |
| 16 | Defect catalogue | 8 classes. Contract: missing required field, invalid format, missing `x-fapi-interaction-id`, undeclared field. Business: inconsistent balance, broken pagination, consent not enforced, transaction outside the window | Business defects keep the response valid against the spec, so each layer is measured on its own. `undeclared-field` measures what schema validation cannot see. The four classes of the original backlog and a 10-class version were the alternatives. See [defects.md](defects.md). |
| 17 | Defect selection | Deterministic: SHA-256 of seed, method, path, sorted query and consent; per-class rates; at most one defect per response | Reproducible regardless of call order or concurrency, and the validators cannot steer it. A seeded random sequence breaks under parallel calls; a fixed campaign has no rate and can be learned. |
| 18 | Labels (ground truth) | JSONL for every exchange, clean included, in `s3://lakehouse/labels/run=<id>/`, written with boto3 | Precision needs the negatives. The same JSONL-in-S3 shape as the validator results (item 3); Spark reads both. Writing to Iceberg from the proxy (pyiceberg) would tie it to the catalog and to concurrent commits. |
